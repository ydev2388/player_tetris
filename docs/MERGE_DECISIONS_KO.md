## 1. 6~10층 및 구역 선택

### 게임에서 보이는 차이

- `develop`: GAME START 뒤 `1~5층`과 `6~10층` 구역을 고르고, 구역 안에서 다섯 층을 선택한다. 5층과 10층이 보스 층이다.
- `9-1차`: 한 화면에서 1~5 스테이지만 선택하며 5층만 보스다.

### 동작 및 데이터 영향

- 스테이지 수가 5개에서 10개로 늘어난다.
- 5의 배수 층을 보스 층으로 판정한다.
- 기존 저장 데이터에 6층 키가 없고 5층을 클리어했다면 6층을 한 번 자동 해금한다.
- 무피해 캐릭터 해금 기록은 기존 콘텐츠인 1~5층만 대상으로 유지한다.

### 선택

- [x] `develop`: 10층과 구역 선택을 사용한다. **선택됨**
- [ ] `9-1차`: 5층 구조를 유지한다.

선택 이유: 사용자가 develop 버전 채택을 명시했다. 10층 진행, 구역 선택, 5·10층 보스 판정과 기존 세이브 마이그레이션을 유지한다.

## 2. 얼음 블록

### 게임에서 보이는 차이

- `develop`: 7층부터 일부 블록에 얼음 외형이 붙고, 그 위에서는 천천히 가속하고 거의 감속하지 않아 미끄러진다. 얼음 벽에는 매달릴 수 없다.
- `9-1차`: 일반 블록과 공격 반사 가시 블록만 존재한다.

### 동작 및 데이터 영향

- 보드가 셀별 얼음 여부를 별도 저장하며 줄 삭제·블록 이동 뒤에도 상태를 보존한다.
- 활성 피스와 고정 블록의 얼음 판정을 통합한다.
- 얼음 블록은 가시처럼 보일 수 있지만 공격 반사 피해는 주지 않는다.

### 선택

- [x] `develop`: 얼음 블록을 사용한다. **선택됨**
- [ ] `9-1차`: 얼음 블록을 제외한다.

선택 이유: 사용자가 develop의 얼음 기능 채택을 선택했다. 얼음 셀 상태 보존, 낮은 마찰, 얼음 벽 매달리기 금지와 전용 표현을 함께 유지한다.

## 3. 9·10층 고드름

### 게임에서 보이는 차이

- `develop`: 낙하 위치에 경고선과 점이 표시된 뒤 고드름이 떨어진다. 캐릭터에 닿으면 생명을 잃고, 활성·고정 블록이나 바닥에 닿으면 사라진다.
- `9-1차`: 고드름 공격이 없다.

### 의존성

- 1번의 6~10층이 선택되어야 한다.
- 2번 얼음 블록과 독립적으로 끌 수 있지만, 함께 사용할 때 원래 층 디자인이 완성된다.

### 선택

- [x] `develop`: 9·10층 고드름을 사용한다. **선택됨**
- [ ] `9-1차`: 고드름을 제외한다.

선택 이유: 사용자가 develop의 고드름 공격 채택을 선택했다. 경고 표시, 낙하 이동, 캐릭터 피해와 활성·고정 블록 및 바닥 충돌 처리를 함께 유지한다.

- 전용 보스 이미지와 피격·사망 상태, 지연된 클리어 전환을 함께 반영한다.

### 선택

- [x] `develop`: 10층 얼음 보스를 사용한다. **선택됨**
- [ ] `9-1차`: 10층 보스를 제외한다.

선택 이유: 사용자가 develop의 10층 얼음 보스를 채택했다. 전용 보스 자산, 피격 오버레이, 사망 애니메이션과 애니메이션 종료 후 클리어되는 전환을 함께 유지한다.

- [ ] `9-1차`: 도전 모드를 제외한다.

선택 이유: 사용자가 develop의 도전 모드를 채택했다. 10층 클리어 후 해금, 제한시간과 층 기믹이 없는 플레이, 최고 삭제 줄 수 저장을 함께 유지한다.

## 6. 벽·코너 오르기와 입력 안정화

### 게임에서 보이는 차이

- `9-1차`: 움직이는 활성 블록 모서리를 오를 때 착지점이 블록을 따라가고, 블록이 고정되면 고정 블록으로 추적 대상을 넘긴다. 외벽 최상단에서는 자동으로 안쪽에 떨어진다.
- `9-1차`: 오르기 키를 설정 화면에서 바꿀 수 있고, 메뉴를 Z로 닫은 입력이 즉시 점프로 이어지지 않는다.
- `develop`: 코너 오르기 추적이 단순하지만 얼음 벽 매달리기 금지를 알고 있다.

### 통합 원칙

- `9-1차`의 이동 블록 추적·고정 블록 인계·외벽 이탈·발판 시각 정렬·입력 action을 보존한다.
- `develop`의 얼음 셀 판정을 결합해 얼음 벽에서는 매달리기와 코너 오르기를 시작하지 않는다.

### 선택

- [x] 수동 통합: 양쪽 안정화 기능을 모두 사용한다. **선택됨**
- [ ] `develop`: 단순한 코너 오르기를 유지한다.
- [ ] `9-1차`: 얼음 제한 없이 9-1차 동작만 사용한다. 2번 선택 시 비권장.

선택 이유: 사용자가 양쪽 기능의 통합을 요청했다. `9-1차`의 이동 블록 추적, 고정 블록 인계, 줄 삭제 뒤 지지면 보정, 외벽 상단 이탈, 발판 시각 정렬, 재지정 가능한 오르기 입력과 메뉴 Z 입력 억제를 유지하고, `develop`의 얼음 이동 및 얼음 벽 매달리기 금지를 함께 적용한다.

- `develop`: 별 개수와 1~5층 무피해 조건으로만 캐릭터를 해금한다.

### 선택

- [ ] 제외: 릴리스에서 정상 해금 조건만 사용한다. **권장**
- [ ] 디버그 전용: 디버그 기능이 활성화된 빌드에서만 0 키를 허용한다.
- [x] `9-1차`: 릴리스에서도 0 키 해금을 허용한다. **선택됨**

선택 이유: 사용자가 0 키 해금 기능을 유지하도록 명시했다. 숫자열 0과 키패드 0 모두에서 전체 캐릭터 선택 제한을 해제하고, 별·재화·스테이지 기록은 변경하지 않은 채 해금 상태만 저장한다. 진행 데이터 초기화 시 이 해금 상태도 함께 초기화한다.

## 8. 중국어 지원

### 게임에서 보이는 차이

- `9-1차`: 한국어·영어·중국어를 순환 선택하며 언어별 사전과 안전한 fallback을 사용한다.
- `develop`: 한국어·영어만 지원하고 중국어 locale은 한국어로 정규화한다.

### 통합 원칙

- 중국어를 선택하면 `9-1차`의 3개 언어 구조를 기준으로 삼는다.
- 6~10층, 구역 선택, 도전 모드, 얼음 기믹 문구에 중국어 번역을 추가한다.
- 누락 문구는 영어로 fallback하고 코드나 키 자체가 화면에 노출되지 않게 한다.

### 선택

- [x] 수동 통합: 3개 언어와 develop 신규 문구를 함께 지원한다. **선택됨**
- [ ] `develop`: 한국어·영어만 유지한다.

선택 이유: 사용자가 양쪽 언어 기능의 통합을 요청했다. `9-1차`의 한국어·영어·중국어 번역 catalog와 영어 fallback을 적용하고, `develop`의 6~10층 구역, 보스 표기, 도전 모드, 결과·실패 화면과 고드름 피해 문구를 중국어로 보완한다. 메뉴뿐 아니라 튜토리얼과 게임 HUD에도 같은 언어 규칙을 사용한다.
